# Accessible Components: Custom vs Shadcn/ui

This document compares the interactive components I built from scratch against the ones generated by `shadcn/ui` (which are built on top of Radix UI primitives).

## What shadcn/ui (Radix) Handled That We Missed

While our custom components successfully met the baseline W3C ARIA Authoring Practices Guide requirements (keyboard operability, focus management, ARIA roles), analyzing the `shadcn/ui` source reveals several advanced edge cases and robust accessibility features that we missed:

### 1. Robust Scroll Locking and Body Padding (Dialog)
In our custom `Modal`, we simply trapped focus and rendered a fixed backdrop. However, we forgot to prevent the background page from scrolling (`body { overflow: hidden }`). 
If you inspect the Radix UI Dialog used by shadcn, you'll see it uses a sophisticated `RemoveScroll` utility. Not only does it lock the body scroll, but it also calculates the width of the user's scrollbar and adds right-padding to the `body` element. This prevents the entire page content from "jumping" left and right when the scrollbar appears and disappears.

### 2. Rendering into a Portal (Dialog)
Our custom `Modal` renders directly inline where it is placed in the React tree. This makes it highly vulnerable to CSS `z-index` stacking context issues (e.g., if a parent element has `overflow: hidden` or a lower `z-index`, the modal might be cut off or appear behind other elements).
The shadcn `Dialog` (via Radix) uses React Portals (`DialogPortal`) to append the modal content directly to the `document.body`. This guarantees it always sits on top of all other DOM elements, immune to parent CSS constraints.

### 3. Screen Reader Announcements and SSR Safety (Tabs)
In our custom `Tabs` component, we used a basic `id` generation strategy. While functional, it isn't strictly SSR (Server-Side Rendering) safe without Next.js `useId()`, and it lacks robust screen reader context.
The shadcn `Tabs` component automatically handles SSR-safe ID generation for every tab and panel pair. More importantly, it manages `dir` (Directionality) context for RTL (Right-to-Left) languages, automatically reversing the arrow-key navigation logic, which our custom implementation completely ignored.
